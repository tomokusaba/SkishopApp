# ADR-0008: PCI DSS 非保持化方針の採用

## ステータス

承認済み

## コンテキスト

SkiShop EC プラットフォームではクレジットカード決済を提供する。PCI DSS（Payment Card Industry Data Security Standard）への準拠レベルを決定する必要がある。カード情報の取り扱い範囲によって準拠コスト・運用負荷が大きく異なる。

## 決定

クレジットカード情報を自社サーバーに**一切保存しない非保持化方針**を採用する。決済は外部 PSP（Stripe 等）の **Hosted Payment Page**（Stripe Checkout）を使用し、カード情報はブラウザから直接 PSP に送信される。自社サービスが扱うのは決済トークンのみ。PCI DSS の **SAQ A** レベルを適用する。

## 理由

### 検討した代替案

| 代替案 | PCI DSS レベル | メリット | デメリット |
|-------|-------------|---------|----------|
| **Hosted Payment Page（採用）** | SAQ A | カード情報が自社システムを通過しない、準拠コスト最小 | UX の制約（ページ遷移が発生） |
| **Stripe.js Tokenization（インラインフォーム）** | SAQ A-EP | UX が良い（ページ遷移なし） | JavaScript のセキュリティ管理が必要 |
| **サーバーサイドカード処理** | SAQ D | 完全なカスタマイズが可能 | 最も厳格な PCI DSS 準拠要件、運用コスト・監査コストが極めて高い |

### 選択理由

1. **セキュリティリスクの最小化**: カード番号（PAN）、CVV/CVC、有効期限が自社インフラを一切通過しない
2. **準拠コストの最小化**: SAQ A-EP は SAQ D に比べて大幅に要件が少なく、監査コストが低い
3. **運用負荷の低減**: カード情報の暗号化・保存・アクセス制御・ログ管理が不要
4. **SkiShop の規模に適合**: 年間 GMV ¥500M 規模の EC サイトにとって、SAQ D 準拠は過剰投資

## 結果

### ポジティブ

- カード情報漏洩リスクの根本的排除
- PCI DSS 準拠の監査・運用コスト最小化
- PSP が提供する不正検知・3D Secure を活用可能

### ネガティブ

- Hosted Payment Page へのリダイレクトが発生し、チェックアウト UX に影響（リダイレクト UX 設計で緩和）
- PSP への依存度が高く、PSP 障害がチェックアウト不能に直結（フォールバック PSP の検討が将来課題）
- PSP の手数料率に依存（3.6% + ¥40/件 程度）
