# ADR-0007: RFC 9457 Problem Details のエラーレスポンス標準化

## ステータス

承認済み

## コンテキスト

マイクロサービスアーキテクチャにおいて、全サービスが統一的なエラーレスポンス形式を返す必要がある。クライアント（フロントエンド、他サービス）がエラーを一貫して処理できるように、標準化されたエラーレスポンス形式を定める必要がある。

## 決定

全 API のエラーレスポンスを **RFC 9457 Problem Details for HTTP APIs** に準拠した形式に統一する。ASP.NET Core の `TypedResults.Problem()` を使用してエラーレスポンスを生成する。カスタムエンベロープ方式（`success`, `data`, `error`）は採用しない。

## 理由

### 検討した代替案

| 代替案 | メリット | デメリット |
|-------|---------|----------|
| **RFC 9457 Problem Details（採用）** | 業界標準、ASP.NET Core ネイティブサポート、機械可読 | フィールドが固定的（extension で拡張可能） |
| **カスタムエンベロープ** | 自由な設計が可能 | 標準化されていない、各チームで解釈が異なるリスク |
| **HTTP ステータスコードのみ** | 最もシンプル | エラーの詳細情報が不足、デバッグが困難 |

### 選択理由

1. **業界標準**: RFC 9457 は HTTP エラーレスポンスの国際標準であり、クライアントライブラリやツールが広くサポート
2. **ASP.NET Core ネイティブサポート**: `TypedResults.Problem()` でゼロ設定で生成可能
3. **AGENTS.md との整合**: AGENTS.md §4.7 で RFC 9457 が必須と規定
4. **機械可読**: `type`, `title`, `status`, `detail` フィールドにより、クライアントがプログラマティカルにエラーを処理可能

## 結果

### ポジティブ

- 全サービスで統一的なエラーレスポンスが返され、フロントエンドのエラーハンドリングが簡素化
- `IExceptionHandler` によるグローバル例外ハンドラーで一元的にエラーレスポンスを生成
- スタックトレースがクライアントに露出しない（`DetailedErrors: false`）

### ネガティブ

- レスポンスに含まれるフィールドが RFC に制約される（`extensions` フィールドでカスタム情報を追加可能）
